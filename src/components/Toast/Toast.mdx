# Toast

The Toast component provides lightweight, temporary feedback messages for users after an action occurs.

Toasts are commonly used for:

- Successful actions
- Errors or failures
- Warnings that require attention
- Informational updates

The component supports:

- Multiple variants
- Icons
- Auto-dismiss behavior
- Manual dismissal
- Animated entrance and exit transitions
- Provider-based state management

# Usage

Toast notifications are managed through the `ToastProvider`.

Wrap your application with the provider:

```tsx
<ToastProvider>
  <App />
  <ToastContainer />
</ToastProvider>
````

Then use the `useToast` hook to trigger notifications:

```tsx
const { addToast } = useToast();

addToast({
  title: "Profile updated",
  description: "Your changes were saved successfully.",
  variant: "success",
});
```

# Behavior

## Auto Dismiss

Toasts automatically dismiss after a default duration.

The lifecycle is:

```
Toast appears
      ↓
Timer starts
      ↓
Closing animation begins
      ↓
Toast is removed
```

---

## Manual Dismiss

Users can manually close a toast using the close button.

Manual dismissal uses the same closing animation as auto-dismiss.

---

## Multiple Toasts

Multiple notifications can appear at the same time.

Toasts are stacked vertically and managed independently.

# Accessibility

Toast notifications follow accessible feedback patterns:

* Uses semantic status messaging.
* Error notifications use assertive alert behavior.
* Icons are decorative and hidden from screen readers.
* Users can manually dismiss notifications.
* Notifications remain readable with supporting text.

---

# Design Notes

Toast uses semantic feedback tokens rather than hardcoded colors.

Variants consume the design system feedback palette:

* Success uses success tokens.
* Error uses error tokens.
* Warning uses warning tokens.
* Info uses information tokens.

This keeps Toast consistent with other feedback components such as Alert.
